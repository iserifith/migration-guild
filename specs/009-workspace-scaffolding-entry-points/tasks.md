## MVP vs incremental boundaries

- **MVP** = Phase 0 docs + Phase 1 (US1, #116, P1) + Phase 2's US2 portion (#117, P1, T020-T022/T027/T029). Both are P1 silent-failure/onboarding breaks (build crash + silent logical skip).

P2 (annoying, not silently broken; operator can work around manually) BUT MUST ship in the same `runInstall()` edit as US2 (SC-004, spec Dependency). The shared-code-path constraint overrides the priority split for delivery — Phase 2 delivers US2+US3 together.
- All three user stories ship in this single feature run; MVP/incremental governs prioritization and review emphasis, not whether US3 is deferred.
